# Work Rhythm 改进落地方案 V3

> 生效日期：2026-08-21  
> 本文是当前唯一有效的产品、设计与开发执行基准。它整合并替代 `development-baseline-v2.md` 中已完成或已被新决策覆盖的内容；旧文档保留用于追溯。

## 1. 本次改进要解决什么

Work Rhythm 的核心计时、活动、休息和本地保存已完成 MVP。接下来的工作不是扩展成任务管理或数据大屏，而是把已有能力收敛成两种清晰体验：

1. **浮窗**：工作时一眼看懂、几乎不打扰。
2. **复盘窗口**：结束后可信地看见一天的专注节律和长期投入。

本次以一套连续的完整计划实施，不再把浮窗、数据和统计拆成多个独立产品阶段。开发中仍应持续编译、测试和视觉检查；全部完成后再进行一次整体用户验收。

## 2. 已确认的产品决策

| 决策项 | 结论 |
| --- | --- |
| 产品形态 | 本地优先的原生 macOS 应用；不回到 Tauri、React 或网页容器。 |
| 浮窗风格 | 透明或半透明、无品牌 Logo、无版本号、无说明性噪音；以中性黑白灰和一个克制强调色为主。 |
| 视觉参考 | 借鉴 ChatGPT 与 Claude 的留白、层级、低饱和色和单一主操作原则；不复制品牌、图标、代码或网页布局。 |
| 专注数据 | 专注记录为不可编辑的时间事实；正式版不允许手动加时、减时、补录、删除或改写任何专注数据。 |
| 暂停口径 | 点击暂停、开始休息、系统睡眠后的时间不计入专注，也不计入某个时段的柱图。浮窗隐藏或切换到其他 App 不自动暂停。 |
| 分时图粒度 | 按自然日的 **1 小时**聚合；每柱最多显示该小时 60 分钟有效专注。 |
| 统计边界 | 做节律与投入复盘，不做效率评分、打卡、排名、待办、日历、云同步或“中断时长”压力指标。 |
| 用户数据 | 继续本机保存、无账号、无遥测、无后台网络请求。 |

## 3. 技术选择与复用原则

继续使用现有的 Swift + SwiftUI + AppKit `NSPanel` 架构。它已经满足无边框浮窗、菜单栏与 macOS 原生交互，不应为了改造界面而更换技术栈。

### 3.1 采用成熟系统能力

| 需求 | 采用方式 | 原因 |
| --- | --- | --- |
| 统计图表 | Apple **Swift Charts**（`Chart`、`BarMark`、`RuleMark`、`ChartProxy`） | 原生支持 macOS 13+、堆叠柱图、悬停详情和深浅色，无须自行绘制图表框架。 |
| 活动选择与次要操作 | SwiftUI `Menu`、`Picker`、`Popover`、SF Symbols | 使用系统成熟菜单行为，键盘与辅助功能自然可用。 |
| 透明与层次 | SwiftUI `Material`、系统语义色、`NSVisualEffectView`（仅在需要时） | 自动适配壁纸、深浅色和系统对比度。 |
| 日期选择 | 系统 `DatePicker`、工具栏日期跳转 | 不引入日历依赖。 |
| 测试 | Swift Package 自动检查、可注入 `Date` / `Calendar` | 覆盖跨日、暂停、睡眠和整点归集，避免依赖真实等待。 |

Swift Charts 是本项目的图表基线，而不是从零手写 Canvas 图表。只有在原生 Charts 无法满足已确认的交互时，才评估 MIT/Apache-2.0 许可的开源组件；引入前必须检查维护状态、许可证、macOS 兼容性和是否会破坏原生外观。不得直接复制来源不明的 UI 代码。

### 3.2 数据层保持轻量

当前个人使用规模下，Codable JSON 足够保存活动、计时状态和专注片段。统计只需在内存中聚合几十至数千条记录；不为了图表提前迁移 SQLite 或 SwiftData。只有出现历史查询性能、筛选或备份需求时，再独立评估迁移。

## 4. 数据可信度：专注记录不可修改

### 4.1 正式记录模型

正式记录统一为不可变的 `FocusSegment`：

```text
id · activityID · startedAt · endedAt
```

有效时长始终由 `endedAt - startedAt` 推导，不再保存或暴露可单独修改的 `focusedSeconds`。记录只由计时状态转换生成：

- 开始或继续：在内存中打开一段专注；
- 暂停、结束、休息提醒、开始休息、Mac 睡眠：封存当前专注段并原子写入；
- 继续后：建立新的段，暂停间隔不属于任何记录；
- 正在进行的段：仅以临时片段参与浮窗与统计预览，结束前不每秒落盘。

必须删除 `adjustRecord` 和复盘页的 `−5 / +5` 控件，也不保留可见的调试加时控件。计时验证使用可注入时间和自动检查完成；若未来确需临时调试入口，它必须编译在 `DEBUG` 条件内、使用隔离数据文件，且不得出现在正式界面、菜单或快捷键中。

### 4.2 统计统一从片段推导

“今日累计”不能再读取计时器的历史累计字段，而是读取所有已封存片段加上当前临时片段，并按本地自然日求交集。这样跨午夜、暂停、休息和重启后的口径一致。

对已存在的调试数据，采用版本化迁移：旧的 `focusedSeconds` 仅用于兼容读取；一旦其与起止时间不一致，不能将其带入正式统计。正式数据不会被自动“修正”或静默改写。

本地文件无法在拥有本机完全控制权的情况下做到绝对防篡改。当前目标是 **应用内绝不提供修改能力**。如后续确有防文件改写需求，可增加 Keychain 密钥的 HMAC 完整性校验，并在校验失败时明确提示而非继续统计。

## 5. 浮窗设计与实现规范

### 5.1 信息架构

浮窗只保留工作当下必需的信息和动作：

```text
今天累计（圆环）       距下次休息（圆环）

当前活动名称                                      ⌄

开始 / 暂停 / 继续                         ···
```

- 去除 `WORK RHYTHM`、Logo、版本号、测试状态、"仅本机保存"等常驻文案；
- 当前活动是一整行可点击的文字胶囊，例如“看论文  ⌄”；展开后使用原生菜单列出启用活动，选中项使用对勾；底部只有“管理活动…”。
- 默认只显示一个高优先级按钮：空闲为“开始”、专注中为“暂停”、暂停后为“继续”。“结束”、切换活动等收进 `…` 菜单。
- 到休息节点时，浮窗只临时显示“开始休息 / 延后 10 分钟 / 跳过”，不混入普通控制。

### 5.2 视觉语言

- 背景使用 `.ultraThinMaterial` 或 `.regularMaterial`，根据实机可读性选择；无实色大底、无渐变、无玻璃拟态装饰。
- 外轮廓仅保留极细的低对比描边和自然阴影；圆角约 20–24pt。
- 文本采用系统字体；累计数字使用 `.rounded` + `monospacedDigit()`，其余使用常规系统字体。
- 色彩以系统主文字、次级灰为基础。专注仅使用一个低饱和靛蓝/石墨色强调；休息使用低饱和暖灰橙；暂停不做大面积黄色警告。
- 圆环仍是唯一视觉中心。两个圆环不添加重复说明，标签短为“今天”“下次休息”。
- 必须在浅色、深色、浅壁纸、深壁纸及高对比度设置下实机检查，而不是只在单一截图中调色。

## 6. 复盘窗口设计与统计规范

### 6.1 结构

窗口保持单一内容画布：顶部为“复盘”与日期选择；中部为当前日期；下部可切换“今日 / 趋势”。活动管理继续是独立页面，不与数据复盘混排。

窗口建议宽度提升至约 760–820pt，使用 24–32pt 内容留白。不要使用大面积 `GroupBox`、厚边框或多层卡片。一个轻表面承载一组相关信息，图表优先于列表。

### 6.2 今日页（默认入口）

1. **摘要行**：有效专注、专注段数、最长连续专注、首次开始时间。
2. **一日分时专注图**：00:00–24:00 的 24 根柱；每柱表示这一小时的有效专注分钟数，最高 60 分钟。
3. **按活动投入**：当天各活动的时长与比例，最多显示五项，其余折叠。
4. **时段详情**：鼠标悬停某柱时显示“09:00–10:00 · 看论文 · 42 分钟”；点击后可查看该小时内的只读专注片段。

柱图的计算规则：每条 `FocusSegment` 与每个整点小时区间求交集，并按实际重叠秒数相加。暂停、休息和睡眠没有片段，因此自然显示为空白。一个小时内有多个活动时使用低饱和的堆叠颜色；没有活动时不画“中断”。

### 6.3 趋势页

- 最近 7 / 30 天每日有效专注柱图；
- 本月累计与按活动累计；
- 近 30 天最活跃小时；
- 上午、下午、晚上三段的投入分布。

所有数字都可回溯到同一组只读片段。没有数据时展示平静的空状态和“开始一次专注后会在这里出现节律”，不使用零值仪表盘。

## 7. 连续实施清单

以下工作按依赖顺序连续完成，属于同一份改进交付：

1. 清理正式版中的测试和编辑入口；将专注记录收敛为不可变时间片段，并完成旧调试数据兼容策略。
2. 重构“今日累计”和所有统计，使其全部从片段与本地自然日推导；为跨午夜、暂停、睡眠、重启和整点分桶加入自动测试。
3. 抽出小型 `DesignTokens`（间距、圆角、语义色、数字字体），只服务 Work Rhythm 的统一外观，不创建通用 UI 框架。
4. 重写浮窗布局、活动选择器与状态按钮；移除品牌和测试噪音，完成深浅色及不同壁纸实机检查。
5. 以 Swift Charts 实现整点分时柱图、悬停详情和活动堆叠；图表数据只来自只读统计聚合层。
6. 重写复盘窗口为“今日 / 趋势”结构，完成摘要、按活动投入和 7/30 天趋势；活动管理与复盘保持分离。
7. 运行单元测试、启动调试样机完成手工回归，检查拖动、暂停、休息、睡眠、跨午夜、日期切换、无数据、深浅色和数据重启恢复。
8. 进行一次整体视觉与行为验收；确认后再提交代码与必要的少量验收截图。

## 8. 验收标准

- 浮窗在正常工作态没有 Logo、版本号、调试控制或多余说明；视觉在浅色和深色壁纸上稳定、克制、可读。
- 正式界面不存在任何增加、减少、编辑、补录或删除专注数据的能力。
- 暂停、休息、睡眠期间不会使今日累计或任何小时柱增长；隐藏浮窗、切换应用不会误暂停。
- 跨午夜后，昨日和今日的时长分别正确；当前进行中的专注仅计入它实际覆盖的自然日和小时。
- 今日图恒为 24 个整点小时，柱高与有效专注分钟数一致；活动堆叠与原始片段一致。
- 所有摘要、趋势和活动统计都能由同一份只读专注片段复算得到。
- 不引入账号、网络服务、遥测、网页容器或未经审查的第三方依赖。
