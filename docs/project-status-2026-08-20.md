# Work Rhythm 项目现状与重启记录（2026-08-20）

## 结论

现有 Work Rhythm 的 Tauri 桌面端原型已冻结。后续不再围绕它补功能，也不将 Tauri、React、Rust、旧双窗口结构、旧菜单栏或 SQLite 视为下一阶段的前提。

后续仍以 macOS 原生桌面浮窗为最终形态，采用可直接运行的本地调试样机验证，而不是最后才交付完整安装包。当前范围、技术和验收方式见 [`development-plan-v3.md`](development-plan-v3.md)。

## 当前原型保留了什么

现有实现曾是一个 macOS 本地 Tauri 应用，包含活动、计时、休息提醒、统计、导出和 SQLite 本地存储。其源码已从工作目录移除；初始 Git 提交保留完整可恢复历史。既有用户数据不在项目目录内，不会因源码清理而受影响。

## 为什么冻结

1. 技术形态先于产品问题被确定。旧文档把 macOS 桌面应用、双窗口和原生能力预先锁定，但没有先验证这些是否是核心需求。
2. 测试成本过高。验证一个想法需要启动或构建整套原生应用，而不是直接在浏览器中调整并试用。
3. 核心体验未达到可持续使用的水平。例如 Mini Timer 的“今天已学习”实际计算的是当前计时段的时长，不是当天累计；统计与历史浏览也不足以形成有效复盘闭环。
4. 关键可靠性尚未经过真实使用验证，包括睡眠唤醒、跨午夜、时区、通知权限和长期资源占用。

## 下一阶段边界

- 从 macOS 原生 V0 浮窗样机开始，以独立可验收的功能切片推进。
- 不做账号、云同步、公共部署、完整发布包、统计大屏或复杂数据模型，除非当前验收阶段明确需要。
- 只在用户确认前一阶段后，才进入下一阶段；完整应用整合不属于当前优先事项。

## 当前仓库约定

- `main` 保存已确认的项目状态。
- 旧桌面原型仅存在于 Git 历史中，不在工作目录继续保留。
- 新原生实现将位于 `macos/`，从 V0 开始。
- 旧执行文档位于 `docs/archive/`，它们不再是执行基准。
- 当前有效执行基准为 `docs/development-plan-v3.md`；不得沿用旧桌面端基准直接推进开发。
